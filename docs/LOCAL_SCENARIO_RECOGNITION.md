# Ручная проверка сценариев после обучения

Приложение работает на этом компьютере: http://127.0.0.1:8501.
Запуск после перезагрузки — `outputs/Start-Trinity.cmd` в папке задачи.

**Текущее качество низкое:** при исключении проверяемого видео и его дублей из
обучения найдены 4 из 18 оцениваемых положительных меток, а на 19 из 20 нормальных
видео возникли ложные тревоги. Ещё 11 положительных меток не оценены из-за единственного
примера соответствующего типа. Совпадение временного пика с ориентиром ±5 секунд —
2 из 18. Это экспериментальный прототип, результаты нужно проверять вручную.

1. Выберите **Сценарии из таблицы (эксперимент)**.
2. В **Локальных примерах** выберите любой из 42 исходных роликов. Для другого файла выберите **Загрузить MOV**.
3. Нажмите **Анализировать**. Повторно обучать модель для каждого ролика не нужно.
4. Посмотрите оценки всех 18 типов и кадры кандидатов. Временное окно указывает участок высокой оценки модели; это не подтверждённые границы действия.
5. При необходимости сохраните **результат JSON**. Выберите следующий ролик и снова нажмите **Анализировать**.

Режим **Состояние сейфа** сохраняет прежнюю отдельную модель с ручной рамкой сейфа. Сценарный режим анализирует весь кадр; рамка не нужна. Выбранный режим и имя обработанного файла подписываются у результата. Если переключить файл без нового запуска, появляется предупреждение, что результат относится к предыдущему запуску.

## Что именно обучено

18 небольших классификаторов обучаются на визуальных признаках и коротком временном контексте. Предварительно обученная MobileNetV2 заморожена; обучение относится к классификаторам сценариев. Используются только локальные вычисления. На вход распознавания поступают пиксели видео, а не его имя или ответы из таблицы.

Причины нарушений в исходной таблице частично предположительные. Поэтому приложение выдаёт **кандидатов для проверки**, а не доказанное нарушение. «Ниже порога» не означает, что нарушения нет. «Нет поддержки» в отчёте означает, что в соответствующем обучении не было положительных или отрицательных примеров этого типа.

Проверку личности, содержимое отчёта, подключение к сети, принадлежность денег, содержимое сумки и необходимость конкретного действия нельзя подтвердить одним сходством кадров. Слабые метки таблицы не изменяют прежние статусы разметки «На проверке».

## Как сравнивать с таблицей

Откройте **Сравнение со всей таблицей**. Здесь два независимых представления:

- **Вне обучающей группы (OOF):** каждый ролик проверен моделью без этого ролика и его точных копий. Для типа с единственным положительным примером проверить перенос на этот пример невозможно — он отмечен как неподдерживаемый.
- **Финальная модель · обучающие видео:** повторный прогон моделью, обученной на всём доступном наборе. Он показывает воспроизведение знакомых примеров и не является оценкой работы на новых видео.

В таблице сохранены ожидаемые типы, кандидаты модели, неподдерживаемые типы, спорные источники и конфликты одинаковых файлов. X-4 и X-47 содержат одинаковое видео с разными причинами в таблице; X-5 и X-48 — одинаковые нормальные видео. При обучении и проверке дубли всегда остаются одной группой. Для X-4/X-47 обучающие причины объединены, а исходные строки сравниваются отдельно.

Сводные метрики по всем парам «видео–тип» содержат много отрицательных меток. Для оценки полезности смотрите прежде всего полноту обнаружения положительных типов, ложные срабатывания на нормальных видео и долю неподдерживаемых примеров. Отметки времени сравниваются с ориентиром таблицы с допуском ±5 секунд; точной разметки границ событий нет.

## Воспроизводимость и перенос

Сценарная модель: `artifacts/scenario-model/model.npz`, `metadata.json`, `backbone.onnx`. Отчёты: `report.json`, `comparison.json`, `out-of-fold-predictions.json`. Кэш признаков: `artifacts/scenario-features`. Прежняя модель сейфа находится отдельно в `artifacts/safe-model`.

Для ручной работы на другом компьютере установите `requirements-ml.txt`, создайте `.env` через `scripts/init_env.py`, настройте `ANALYZER_MODE=real`, `ANALYZER_CALLABLE=src.vision.safe_classifier:analyze_video`, `MODEL_PATH=artifacts/safe-model` и `SCENARIO_MODEL_PATH=artifacts/scenario-model`. Запустите API и Streamlit как в README. Личные ключи, исходные видео и база результатов не входят в архив кода и модели.

Список локальных примеров задаётся `SCENARIO_DATASET_MANIFEST`, отчёт в интерфейсе — `SCENARIO_COMPARISON_REPORT`. При переносе обновите пути к видео в копии манифеста; без манифеста остаётся загрузка MOV вручную.

Повторное обучение из обновлённой, отдельно проверенной копии меток:

```powershell
python scripts/extract_scenario_features.py --manifest PATH_TO_MANIFEST --backbone artifacts/scenario-model/backbone.onnx --output artifacts/scenario-features-new
python -m src.training.train_scenarios --manifest PATH_TO_MANIFEST --feature-cache artifacts/scenario-features-new --output artifacts/scenario-model-new
```

Скопируйте проверенные `backbone.onnx` и `BACKBONE-LICENSE.txt` в новую папку модели. Сначала изучите новый отчёт; затем смените `SCENARIO_MODEL_PATH` и перезапустите приложение. Для сравнения всех файлов через настоящий API есть `scripts/run_scenario_batch.py --manifest ... --comparison ... --output ...`; запуск последовательный, чтобы не переполнять очередь.

Архитектура и фиксированные настройки описаны в `docs/scenario-recognition-design.md`. Источники замороженных весов и предобработки: [официальный ONNX Model Zoo](https://github.com/onnx/models/blob/main/validated/vision/classification/mobilenet/README.md). Лицензия Apache-2.0 сохранена рядом с весами. Метод исключения целой группы соответствует принципу [групповой перекрёстной проверки scikit-learn](https://scikit-learn.org/stable/modules/cross_validation.html).
