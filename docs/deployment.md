# Развёртывание: подготовленная конфигурация, без публикации

Сервер, DNS, бюджет и доступ ещё не согласованы. Здесь инструкция для будущего
согласованного окружения; наличие файлов не означает, что сервис опубликован.
Образы и зависимости скачиваются при подготовке. Во время анализа API и UI
подключены только к внутренней Docker-сети. Веса модель должна читать локально.

## Проверка на локальном Docker Engine / Docker Desktop (Linux containers)

Из корня свежего клона, после установки Python-зависимостей:

```powershell
python scripts/init_deploy_secret.py
docker compose -f deploy/compose.json config --quiet
docker compose -f deploy/compose.json up --build -d
docker compose -f deploy/compose.json ps
```

Это локальный запуск: порты API 8000 и UI 8501 привязаны к 127.0.0.1.
По умолчанию работает demo, реальной модели в образе нет. Тестовый MOV создаётся
командой `python scripts/make_synthetic_video.py`. Никаких ZIP и внешних видео
для проверки не нужно. Переход в `real` требует отдельно разрешённого анализатора.

API-ключ хранится в `.secrets/api_key` и монтируется только API и UI как файл.
Он не передаётся в Dockerfile или build-аргументах. Не задавайте одновременно
API_KEY и API_KEY_FILE. `.env` локального запуска и Compose-secret независимы.
На POSIX каталог `.secrets` создаётся с режимом 0700, файл — 0644 для чтения
непривилегированным контейнером. На Windows ограничьте доступ к папке своей учётной
записью средствами ACL. В Compose не используйте чужой каталог с данными.

Контейнеры API/UI работают без root, с read-only корнем, ограничением памяти и
числа процессов. SQLite живёт в volume `jobs`; temporary spool — в `/tmp`.
Нельзя запускать несколько экземпляров API на одном volume. Модель пока не
подключена: её зависимости и read-only mount весов надо добавить после согласования.

Остановка с сохранением результатов:

```powershell
docker compose -f deploy/compose.json down
```

Volume сохраняется. TTL применяется при работающем сервисе и следующем запуске;
остановленный сервис сам данные не удаляет. Удаление volume — отдельная операция
по согласованной политике хранения. Копии и резервные снимки также требуют удаления.

## Публичный вариант — только после согласования конкретного сервера

Нужно согласовать ОС/ресурсы сервера, домен, ответственного, срок хранения и
стоимость. На сервере настроить DNS и входящие 80/443, выбрать фиксированные digest
образов после проверки. Шаблон использует `python:3.12-slim-bookworm` и `caddy:2-alpine`;
это не фиксация всех будущих обновлений образов.

Дополнительный `deploy/compose.public.json` подключает Caddy: HTTPS, API по
`/api/v1/*`, Streamlit по остальным путям. API требует X-API-Key. UI отдельно
защищён Basic Auth: без этого любой посетитель мог бы запускать анализ через
серверный ключ Streamlit. Ключ API нельзя использовать как пароль UI.

До запуска подготовьте `.secrets/ui_users` со строкой `имя bcrypt-хеш`.
Хеш создайте на согласованном сервере командой `caddy hash-password` с интерактивным
вводом пароля; не передавайте пароль аргументом командной строки. Файл должен быть
читаем контейнером и находиться в закрытом каталоге `.secrets`. В нём нет открытого
пароля. Установите SITE_DOMAIN на согласованный домен.

После отдельного разрешения на публикацию:

```powershell
docker compose -f deploy/compose.json -f deploy/compose.public.json config --quiet
docker compose -f deploy/compose.json -f deploy/compose.public.json up --build -d
```

Эти команды открывают публичный доступ. Сейчас они не выполнялись.
Перед сдачей проверить HTTPS, UI без/с паролем, API без/с ключом, synthetic MOV,
ошибки, очередь и результат с другого устройства. Доступность `/healthz` подтверждает
только работу API/очереди/SQLite, не наличие или качество модели.

Проверка сборки предусмотрена в Linux CI. На машине текущего аудита Docker
отсутствовал: сборка образа, TLS и публичная доступность локально не проверены.

Официальные справочники: [Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/),
[внутренние сети](https://docs.docker.com/reference/compose-file/networks/),
[Caddy Basic Auth](https://caddyserver.com/docs/caddyfile/directives/basic_auth).
