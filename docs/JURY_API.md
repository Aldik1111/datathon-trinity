# Запуск API для жюри

Этот профиль делает один конкретный выбор: запрос с полем `file` и заголовком
`X-API-Key` запускает локальный анализатор `bank_scenarios`, а результат проходит
проверку и преобразование в бинарный контракт кейса. Ручная рамка сейфа,
`analysis_type` и действия в Streamlit для такого запроса не нужны.

Изменения API не улучшают распознавание. У модели сохраняются ложные тревоги,
слабая разметка обучающих примеров и ограниченная проверка переноса на новые
видео. Успешная HTTP-проверка подтверждает технический путь запроса, а не
правильность найденного нарушения.

## Почему прежний запуск мог дать другой результат

Старый выбор режима зависел от `ANALYZER_CALLABLE`, `MODEL_PATH` и необязательного
`analysis_type`. Настройки прежнего классификатора сейфа могли отправить обычный
запрос в `safe_state`, которому нужна рамка сейфа. При явном выборе сценариев
внутренний ответ использовал `review_required` / `no_candidate`, а контракт жюри
требует `violation` / `no_violation`.

Теперь профиль задаётся совместно тремя серверными переменными:

```text
ANALYZER_MODE=real
DEFAULT_ANALYSIS_TYPE=jury
JURY_ANALYZER=bank_scenarios
```

Для него используется `SCENARIO_MODEL_PATH`. Клиент не выбирает путь к модели или
Python-функцию. Явный `analysis_type=safe_state` остаётся отдельным прежним режимом:
он использует `MODEL_PATH` и по-прежнему требует `roi`. Явный экспериментальный
`bank_scenarios` также сохраняет собственный контракт кандидатов.

## Как получается бинарный ответ

Применяется фиксированная политика `scenario-threshold-v1`:

1. Видео полностью декодируется локально. Проверяются временная шкала, покрытие
   кадрами и результаты локального анализатора. Технический сбой означает
   `failed`, а не отрицательное решение.
2. Для каждого класса берётся сохранённая в весах поддержка класса и его порог.
   Кандидат появляется только у поддерживаемого класса, когда оценка модели
   достигает этого порога. Новые пороги не подбираются.
3. Для каждого кандидата проверяется совпадение класса, оценки, пикового времени
   и интервала с внутренним результатом. В ответ попадают 1–3 настоящих JPEG-кадра
   из интервала, включая пик. Времена должны соответствовать отсчётам анализатора.
4. Есть хотя бы один корректный кандидат — возвращается `violation`. Это
   операционное бинарное решение модели по её существующему порогу. Оно не
   подтверждает нарушение процедуры или закона. Описания прямо сохраняют эту
   оговорку и не придумывают движения, документы или содержание денежных сумм.
5. Кандидатов нет — `no_violation` разрешён только при полном техническом покрытии
   и поддержке всех 18 классов каталога. Если часть классов неподдерживаема либо
   покрытие недостаточно, задача становится `failed`: такой случай нельзя
   скрывать пустым успешным результатом.

Даже допустимый `no_violation` означает, что модель не нашла признаков в рамках
своей политики и выборки кадров. Это не гарантия отсутствия нарушения: анализ
использует 1 кадр в секунду, а качество модели ограничено. Полное техническое
покрытие означает успешное чтение и обработку видео, а не распознавание всех
коротких действий и не достоверность всех классов.

Дополнительные поля сохраняют `internal_verdict`, `class_results`,
`model_support_policy`, `score_semantics`, `limitations`, `coverage`,
`model_version`, `output_contract`, `jury_policy` и `provenance`. В `provenance`
указаны фактически запущенный анализатор и контрольные суммы входа/весов.
Оценка модели называется `uncalibrated_model_score` и не является вероятностью
доказанного нарушения.

`configs/rules.json` остаётся реестром проверенных нормативных оснований. Пустой
реестр не заменяется придуманными ссылками: события показывают
`rule_status=unverified`. Заполненный и проверенный реестр — отдельная задача
перед утверждением нормативной части проекта.

## Первый запуск в PowerShell

Команды ниже выполняются **в PowerShell**, из корня репозитория. Они создают
отдельное окружение, если его ещё нет. Если уже используется проверенное Python-
окружение проекта с `requirements-ml.txt`, вместо `.venv-jury` укажите его Python.

```powershell
py -3.12 -m venv .venv-jury
.\.venv-jury\Scripts\python.exe -m pip install -r requirements-ml.txt
```

Локальные веса должны уже находиться в
`artifacts/handoff-baseline/scenario-model`: `model.npz`, `metadata.json`,
`backbone.onnx`. Они не включены в Git. Перенесите разрешённые веса отдельно через
согласованный локальный канал. Обучение при запуске не выполняется. Отсутствующая
или не загружающаяся модель не заменяется демонстрационным ответом.

Задайте профиль и введите собственный секрет в скрытом приглашении. Сам ключ
не появляется в команде, истории PowerShell или примере. Сохранённая `.env`
не меняется и не читается при этом запуске.

```powershell
$env:PYTHON_DOTENV_DISABLED = '1'
$jurySecret = Read-Host 'API_KEY для локального сервера' -AsSecureString
$env:API_KEY = [System.Net.NetworkCredential]::new('', $jurySecret).Password
$jurySecret.Dispose()
$env:ANALYZER_MODE = 'real'
$env:DEFAULT_ANALYSIS_TYPE = 'jury'
$env:JURY_ANALYZER = 'bank_scenarios'
$env:SCENARIO_MODEL_PATH = 'artifacts/handoff-baseline/scenario-model'
$env:ANALYZER_CALLABLE = 'src.vision.safe_classifier:analyze_video'
$env:MODEL_PATH = 'artifacts/handoff-baseline/safe-model'
$env:RULES_PATH = 'configs/rules.json'
$env:UPLOAD_DIR = 'artifacts/jury-api/uploads'
$env:API_DB_PATH = 'artifacts/jury-api/jobs.sqlite3'
$env:MAX_UPLOAD_MB = '100'
$env:ANALYZER_TIMEOUT_SEC = '295'
$env:MAX_PENDING_JOBS = '2'
$env:JOB_TTL_SEC = '86400'
.\.venv-jury\Scripts\python.exe -m uvicorn src.api.app:create_app --factory --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

Нужен один процесс Uvicorn: очередь и её исполнитель находятся в этом процессе.
Адрес `127.0.0.1` не публикует сервис в интернете. Пример конфигурации также лежит
в `.env.jury.example`; это справочник значений, он не загружается автоматически.

Серверный бюджет установлен в 295 секунд с запасом до границы 300 секунд.
Загрузка запроса и ожидание в очереди входят в общий бюджет задачи; бесконечного
ожидания очереди перед новым полным тайм-аутом не допускается. Медленная сеть,
нехватка ресурсов или слишком тяжёлый ролик могут привести к понятной ошибке
вместо успешного результата. Гарантировать скорость для всех файлов по одному
быстрому прогону нельзя.

## Один скрипт проверки

Во втором окне PowerShell перейдите в тот же репозиторий, введите тот же ключ и
путь к разрешённому MOV. Медиа обрабатывается локально. Команда не отправляет
`analysis_type`, ROI, путь к весам или произвольный callable.

```powershell
$jurySecret = Read-Host 'Тот же API_KEY' -AsSecureString
$env:API_KEY = [System.Net.NetworkCredential]::new('', $jurySecret).Password
$jurySecret.Dispose()
$juryVideo = Read-Host 'Полный путь к разрешённому MOV'
.\.venv-jury\Scripts\python.exe scripts/check_jury_api.py --url http://127.0.0.1:8000 --video "$juryVideo" --timeout 300
```

Для сохранения компактного отчёта добавьте, например,
`--output artifacts/jury-check.json`. Файл должен быть новым; существующий
файл не перезаписывается. Отчёт содержит время, вердикт, число событий и
декодированных JPEG, версию анализатора и контрольные суммы. В нём нет кадров,
описаний событий, пути видео или ключа. Полный ответ сервера в файл не сохраняется.

Проверка включает:

- `202` после загрузки и совпадение `job_id` на каждом опросе;
- ожидание только `processing`, завершение `done` или явную ошибку при `failed`;
- общий дедлайн от начала POST, включающий загрузку и все запросы GET;
- бинарный вердикт и согласованность непустого/пустого списка событий;
- фактический `bank_scenarios`, `demo=false`, версию, политику и SHA-256 входа;
- длительность по локальному декодированию, покрытие и поддержку классов;
- 1–3 JPEG на событие: строгий base64, маркеры JPEG, декодирование изображения,
  положительные размеры, допустимые времена, принадлежность интервалу и наличие
  пикового кадра;
- отсутствие `NaN` и `Infinity`, в том числе во вложенных дополнительных полях.

Код возврата `0` означает успешную интеграционную проверку. Код `1` означает
ошибку проверки. В ответе с ошибкой выводится фиксированный код без исходного
ответа сервера. Ошибка `analysis_failed` не считается успешным отрицательным
решением. Автоматические перенаправления запрещены. Системные HTTP-прокси
не используются. Удалённый адрес требует явного `--allow-remote` и HTTPS;
для текущей локальной проверки этот флаг не нужен.

Проверить только доступность и настройки сервера можно через защищённый
`GET /api/v1/readiness`. Этот endpoint не заменяет отправку MOV и завершение
реальной задачи: наличие файла весов не означает, что модель успешно загрузилась.

После работы секрет можно убрать из текущего процесса PowerShell:

```powershell
Remove-Item Env:API_KEY
```

## Проверки кода и фактические результаты

Проверка выполнена 18 октября 2026 года в отдельной локальной ветке
`fix/jury-scenario-contract` от актуального `main`, коммит `008aaa0`.
Указанная в поручении папка пользователя Acer отсутствовала на подключённом ПК;
после уточнения репозитория использована существующая копия под пользователем
User. Перед изменениями рабочая копия была чистой. Push, деплой и туннель
не выполнялись. Существующие `.env`, веса, исходные видео и разметка сохранены.

Оригинальный `Кейс_ForteBank.docx` прочитан. Раздел 10 требует перечисленные
`job_id`, `status`, `verdict`, `violations`, `type`, `timecode_sec`, `description`
и `evidence_frames` с `timestamp_sec` / `image_base64`; дополнительных обязательных
полей JSON там нет. Требование объяснить связь с правилом и нормативным источником
есть в разделах 4 и 6. Пустой реестр правил остаётся блокером этой части кейса;
`rule_status=unverified` не является выполнением требования о проверенном источнике.

Финальный полный набор: **370 passed, 1 warning, 2 subtests passed** за
22,63 секунды. Единственное предупреждение — уведомление Starlette об устаревающем
подключении HTTPX. Отдельно прошли 28 адресных тестов API/очереди, 70 тестов
бинарной политики и 47 тестов клиентского скрипта. Эти числа входят в полный
набор, их не надо прибавлять к 370.

Отдельный процесс Uvicorn с настоящей очередью и исходными локальными весами
принял три запроса только с `file` и `X-API-Key`. Ни анализатор, ни веса не
подменялись. `MODEL_PATH` и прежний callable намеренно указывали на safe-state,
а новый профиль выбрал `src.vision.scenario_classifier:analyze_video`.
Версия модели: `scenario-cpu-v1-2c1aeaed514af1c5`.

| Проверка | Длительность MOV | От начала POST до проверенного GET | Ответ | События / JPEG |
| --- | ---: | ---: | --- | ---: |

Срабатывание на искусственных фигурах дополнительно показывает, почему
успешный API-запрос нельзя считать проверкой качества распознавания.
Записи A и B уже относятся к известному набору разработки; их результаты
не являются независимыми метриками качества. Оценки и пороги не подбирались.

Все 19 JPEG положительных ответов дополнительно побайтно сопоставлены с
повторно декодированными исходными кадрами после той же операции уменьшения
и JPEG-кодирования. Проверены совпадение контрольной суммы загруженного видео,
полное покрытие, бинарный JSON, версия модели, ключ на обоих маршрутах,
неизвестная задача и очистка временных MOV/sidecar после каждой задачи.
Контрольные суммы использованных оригиналов, весов и `.env` до и после совпали.
Сервер проверки остановлен. Локальный агрегированный отчёт находится в
`artifacts/jury-http-20261018/verification.json`, подробные ответы и база задач
не включены в Git.

Один промежуточный запуск тестов spawned-worker испытал длительную задержку
исполнения и один тест превысил свой срок ожидания. Причина задержки не
установлена. Отдельный повтор этого теста, повтор всех четырёх тестов
spawned-worker и финальный полный набор прошли без изменения кода между
повторами. Это ещё одна причина отдельно проверять время на целевом компьютере
и под нагрузкой, а не обещать общий SLA по нескольким коротким прогонам.

## Повторить проверки кода

Адресные тесты CLI используют искусственные JPEG/MOV и поддельные HTTP-ответы
для проверки валидатора. Они отдельно от реального прогона модели:

```powershell
.\.venv-jury\Scripts\python.exe -m pytest tests/test_jury_api_check.py -q
.\.venv-jury\Scripts\python.exe -m pytest -q
```

Технический путь POST → очередь → настоящая модель → GET проверен в указанной
локальной конфигурации. Для другого компьютера, другого пути весов или новой
версии модели выполните `check_jury_api.py` повторно до передачи адреса жюри.

Остающиеся ограничения перед сдачей: ложные тревоги и пропуски модели;
недостаточная независимая оценка качества; возможные неподдерживаемые классы у
других весов; незаполненные проверенные нормативные источники; необходимость
проверить скорость на целевом компьютере и реальном диапазоне длительности и
размера видео. Изменение формата JSON не устраняет эти ограничения.
