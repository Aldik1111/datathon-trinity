# Сервис и интеграция Trinity

## Статус и границы

Сервис предоставляет FastAPI, очередь, SQLite, Streamlit и адаптер локальной функции.
Реального анализатора в поставке нет. Demo возвращает явно тестовое событие.
Тесты проверяют инфраструктуру на искусственных изображениях и синтетическом MOV.
Качество распознавания, нормативная квалификация и переносимость не измерены.
Реестр `configs/rules.json` пуст; UI показывает отсутствие подтверждённого основания.

## Локальный запуск для команды

Python 3.12, новый клон актуального main или ветки PR. Из корня:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe scripts/init_env.py
.\.venv\Scripts\python.exe -m pytest tests -q
```

В двух терминалах:

```powershell
.\.venv\Scripts\python.exe -m uvicorn src.api.app:create_app --factory --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

```powershell
.\.venv\Scripts\python.exe -m streamlit run src/ui/app.py --server.address 127.0.0.1 --server.port 8501
```

UI: http://127.0.0.1:8501. Схема API: http://127.0.0.1:8000/docs.
`/healthz` сообщает только о работе API, а не о наличии модели.
Остановка: Ctrl+C в каждом терминале. На Linux: `.venv/bin/python`.
Генератор `.env` не перезаписывает файл и не выводит ключ.

## Контракт участников

- `POST /api/v1/analyze`: multipart `file` с расширением MOV, `X-API-Key`; 202,
  `job_id`, `status=processing`, `demo`.
- `GET /api/v1/jobs/{job_id}`: тот же ключ; `processing`, `done` или `failed`.
- `done`: `verdict` (`violation` / `no_violation`), `violations`, `demo`.
- Событие: `type`, `timecode_sec`, `description`, 1–3 `evidence_frames` с
  `timestamp_sec` и JPEG `image_base64`; дополнительно `rule` и `rule_status`.
- `failed`: безопасное сообщение `error`, без отрицательного вердикта.
- 401: нет/неверный ключ; 400: пустой файл; 413: размер; 415: расширение;
  422: отсутствует multipart-поле; 503: очередь заполнена; 404: задача не найдена/истекла.

Участник 2 предоставляет `analyze_video(video_path) -> AnalysisResult` из
`src/vision/contracts.py`. Сигнатура и dataclass-контракт сохранены.
В `.env`: `ANALYZER_MODE=real`, `ANALYZER_CALLABLE=package.module:analyze_video`,
при необходимости `MODEL_PATH`. Модуль должен входить в установленный Python-пакет
или исходники образа; веса монтируются только локально и только после разрешения на данные.
Отсутствующий модуль даёт `failed` с сообщением `Local model is not installed`.
Облачный AI и идентификация лиц не входят в разрешённый контракт.

Участник 1 передаёт схемы новых разрешённых аннотаций и проверенный реестр правил.
Для источника требуются `rule_id`, `title`, HTTPS `url`, `section`, `checked_at`,
`limitations`, `verified=true`. Флаг ставится после независимой проверки человеком;
сам сервис достоверность источника не устанавливает. Связь события с нормой требует
ручной проверки. Тестовые источники используются только в тестах.

## Очередь, сроки и хранение

Один API-процесс (`--workers 1`), одна реплика и один потребитель очереди.
`MAX_PENDING_JOBS` ограничивает ожидающие и выполняемые задачи вместе;
параллельные загрузки резервируют места. Лимит `ANALYZER_TIMEOUT_SEC` — 1–300 секунд
от регистрации задачи, включая ожидание в очереди и запуск процесса.
Загрузка до регистрации задачи в эти 300 секунд не входит.
Превышение срока завершает дочерний процесс и даёт `failed`.

`MAX_UPLOAD_MB` ограничивает файл; middleware также ограничивает multipart-тело
(допуск 64 KiB), в том числе без Content-Length. Авторизация проверяется до парсинга.
Расширение MOV не гарантирует корректность содержимого: нечитаемый файл даёт `failed`.
Полное декодирование OpenCV не является экспертизой контейнера.

Временный MOV удаляется после успеха, ошибки и штатной остановки. При старте
незавершённые задачи становятся `failed`; загрузки с UUID-именами удаляются,
включая оставшиеся после сбоя до записи SQLite. `UPLOAD_DIR` принадлежит сервису:
не хранить там исходники или другие документы. Готовые результаты и JPEG сохраняются
до `JOB_TTL_SEC`, очистка периодическая (до 60 секунд задержки) и при запросах.
SQLite сохраняется между перезапусками. Не использовать сетевой общий диск и несколько реплик.

API пишет только идентификатор задачи и класс ошибки. Вывод дочернего анализатора
и нативного декодера подавлен; исключения модели заменяются фиксированными сообщениями.
Не добавлять вывод тела запроса, ключей, JPEG или результата в журналы.
`.env`, видео, базы и веса исключены из Git; Docker собирается по белому списку файлов.

## Подготовленная конфигурация Docker

Docker Engine с Compose v2. После создания `.env` локально:

```text
docker compose config --quiet
docker compose up --build -d
docker compose ps
docker compose down
```

API и UI доступны только на loopback. Внутренняя сеть блокирует их прямой выход
в интернет. API работает без root, с ограничениями памяти/PID и read-only корнем;
`service-state` хранит SQLite и загрузки, `/tmp` — ограниченный tmpfs.
Streamlit имеет собственный лимит загрузки, согласованный через Compose с API.
Установка зависимостей при сборке требует сети; обработка видео облачным AI не выполняется.

Синтетическая проверка Linux-образа без внешней сети:

```text
docker build --target test -t trinity-test .
docker run --rm --network none trinity-test
```

Эти команды также включены в CI. Локально Docker отсутствовал, поэтому контейнерный
запуск и HTTPS здесь не подтверждены; результаты смотреть в Actions на текущем PR.

## Публичная среда — только после согласования

До запуска согласовать конкретный сервер/владельца, домен, доступ жюри, сроки хранения
и лимиты ресурсов. Эта работа не создаёт сервер, DNS, платные ресурсы или публичный URL.
Подготовлена схема для одного Linux-хоста: HTTPS Caddy → Streamlit → внутренний FastAPI.
API-ключ остаётся на сервере; публичный API в этой схеме не открыт.

После согласования направить DNS на хост и открыть только 80/443. Сформировать пароль
жюри и bcrypt-хеш интерактивно (`docker run --rm -it caddy:2 caddy hash-password`),
внести `PUBLIC_DOMAIN`, `JURY_USER`, `JURY_PASSWORD_HASH` в закрытый `.env`.
Хеш заключить в одинарные кавычки, чтобы сохранить `$`; пароль не записывать в файл.
Не выводить `docker compose config` без `--quiet`: он раскрывает переменные.

Только для согласованной среды:

```text
docker compose -f compose.yaml -f deploy/compose.public.yaml config --quiet
docker compose -f compose.yaml -f deploy/compose.public.yaml up --build -d
```

Caddy выдаёт TLS-сертификат и требует отдельный вход жюри. Access-log не включён.
Лимит reverse proxy — 106 MB, рассчитан на стандартный файл до 100 MiB с учётом
семантики единиц Caddy; при изменении MAX_UPLOAD_MB согласовать лимит proxy.
Проверить HTTPS, отказ без пароля, WebSocket UI, синтетическую загрузку, статусы,
перезапуск и очистку на выбранном хосте перед допуском новых данных.
Пароль жюри общий: это демонстрация для доверенной группы, не многопользовательская
система с изоляцией пользователей. Горизонтальное масштабирование не поддерживается.

Справка: [Caddy basic_auth](https://caddyserver.com/docs/caddyfile/directives/basic_auth),
[Docker Compose](https://docs.docker.com/compose/).
