# Передача сервиса команде

Работа начата новым клонированием очищенного main `d47d57b` в отдельную ветку
`feature/service-integration-audit`. Старые ветки и артефакты в неё не переносились.
Проверки используют только программно созданные изображения, MOV с геометрическими фигурами
и искусственные ответы анализатора. Данные для обучения не предоставлялись и не использовались.

## Локальный запуск — Python 3.12

Из корня нового клона:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe scripts/init_env.py
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe scripts/smoke_test.py
```

Генератор не перезаписывает .env и не печатает ключ. Для демонстрации явно оставьте
`ANALYZER_MODE=demo`. Для подключения модели поставьте `real`, настройте
`ANALYZER_CALLABLE=ваш.модуль:analyze_video` и локальный `MODEL_PATH`.
Отсутствие анализатора в real приводит к failed с фиксированной понятной ошибкой.

Первый терминал:

```powershell
.\.venv\Scripts\python.exe -m uvicorn src.api.app:create_app --factory --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

Второй терминал:

```powershell
.\.venv\Scripts\python.exe -m streamlit run src/ui/app.py --server.address 127.0.0.1 --server.port 8501
```

UI: http://127.0.0.1:8501. Ключ находится только в окружении/.env сервера.
На Linux используйте `.venv/bin/python`. Остановка — Ctrl+C.

## Контракт

- `POST /api/v1/analyze`: multipart `file`, расширение MOV, заголовок `X-API-Key`; ответ 202,
  `job_id`, `status=processing`, `demo`.
- `GET /api/v1/jobs/{job_id}`: тот же заголовок; `processing`, `done` или `failed`.
- При done: `verdict=no_violation|violation`, `violations`; каждый элемент содержит
  `type`, `timecode_sec`, `description`, 1–3 `evidence_frames` с `timestamp_sec` и JPEG `image_base64`.
- `violation` требует событий, `no_violation` требует пустого списка. Ошибка не содержит verdict.
- В demo искусственное событие обозначено в JSON, описании и интерфейсе. Кадр служит только
  проверкой отображения; UI не заявляет обнаруженное нарушение.
- Нормативное основание выводится только при `rule_status=verified`. Проверка источника
  не доказывает применимость нормы к конкретному событию: это проверяет человек.

Функция модели по-прежнему `analyze_video(video_path) -> AnalysisResult` из
`src/vision/contracts.py`. Адаптер проверяет вердикт, времена, описание и JPEG. Входные
видео обрабатываются локальным процессом; облачных AI-вызовов и идентификации лиц нет.
API-ключ не передаётся анализатору через Settings и удаляется из его окружения;
сырой stdout/stderr дочернего анализатора подавлен. Анализатор должен быть доверенным
локальным кодом: дочерний процесс не является изоляцией от чтения всех файлов сервера.

## Жизненный цикл

Один API-процесс и последовательный worker. Размер очереди ограничивает все принятые
незавершённые задачи. Тайм-аут 1–300 с отсчитывается от принятия задачи после загрузки и
включает очередь; просроченные ожидающие задачи завершаются failed при проверке раз в секунду.
Дочерний процесс завершается при превышении срока. Ошибки и завершение очищают MOV.

На старте незавершённые записи SQLite становятся failed. Дополнительно удаляются
UUID.mov без записи, оставшиеся при аварии до записи в базу. Файлы с произвольными именами
и пути вне UPLOAD_DIR уборщик не удаляет. Завершённые результаты переживают перезапуск;
после JOB_TTL_SEC удаляются вместе с кадрами. Активные задачи TTL-очистка не удаляет.
Содержимое SQLite чувствительное; храните на защищённом диске с ограниченным доступом.
Удаление строк SQLite не является гарантированным физическим стиранием носителя.

## Проверено и не проверено

На Windows с Python 3.12 проверены API, авторизация до разбора multipart, ограничения размера,
chunked-загрузка, конкурентный приём, очередь, тайм-аут, перезапуск, блокировка второго API,
удаление файлов, JSON и JPEG, UI и нормативные статусы. Отдельный Uvicorn-процесс на синтетическом
MOV возвращает demo=done, real без модели=failed. Streamlit AppTest загружает синтетический MOV
в настоящий HTTP-сервер, дожидается done и отображает JPEG.

Итоговый запуск: **49 passed**. Единственное предупреждение — deprecation использования
httpx в Starlette TestClient; ошибок тестов нет. Отдельный `scripts/smoke_test.py` также прошёл
для demo и real без модели. Эти результаты относятся к технической интеграции.

Проверена схема compose.json по официальной JSON Schema compose-spec. Docker в рабочей
среде отсутствует: сборка Linux-образа, Compose, Caddy, TLS и доступность публичного адреса
ещё не проверены запуском. Публикации нет.

Реальной модели, проверенных нормативных связей и разрешённых новых данных нет.
Качество распознавания и переносимость на другие условия не измерялись. configs/rules.json
остаётся пустым; тестовые нормативные записи не добавлены в поставку. До содержательной оценки
участник 2 должен подключить локальный анализатор, а команда — получить разрешённые данные,
разметку и подтвердить источники РК.
