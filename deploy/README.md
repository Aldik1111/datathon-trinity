# Шаблон публичного развёртывания — запуск пока не согласован

Подготовлен вариант для одного согласованного Linux-хоста с Docker Compose v2,
доменом и входящими портами 80/443. Ресурсы не создавались, публичного URL нет.
В этой среде Docker отсутствует; сборка и запуск контейнеров ещё не проверены.
JSON конфигурация проверена по официальной схеме compose-spec.

Сначала согласовать с владельцем конкретный хост, стоимость, домен, доступ жюри, регион
и условия хранения разрешённых видео. Следующие команды выполняет оператор после согласования.
Прежние запрещённые данные в эту среду не переносить. Облачные AI API не подключать.

## Конфигурация

1. Клонировать актуальную проверенную ветку и создать .env через `python scripts/init_env.py`.
2. Для технического показа явно выбрать `ANALYZER_MODE=demo`. Значение real без модели
   корректно приводит к failed; фиктивная модель не подставляется.
3. В .env указать согласованный DOMAIN и отдельный JURY_USER. Сгенерировать хеш пароля:

```sh
docker run --rm -it caddy:2.10 caddy hash-password
```

Пароль вводится интерактивно. Поместить хеш в `.env` как `JURY_PASSWORD_HASH='…'`,
с одинарными кавычками, сохраняющими символы `$`. Это пароль доступа жюри, не API_KEY.
Доступ к .env ограничить владельцем. Не публиковать .env, вывод окружения или ключи.

4. Подключить DNS домена к согласованному серверу. На новом выделенном хосте:

```sh
docker compose -f compose.json config --quiet
docker compose -f compose.json up -d --build
docker compose -f compose.json ps
```

`config --quiet` проверяет конфигурацию, не печатая подставленные секреты.
Первые две команды могут скачивать образы и пакеты; сам анализатор работает локально.
Прокси получает TLS-сертификат для домена. Публичный UI после успешной проверки будет
доступен по `https://<согласованный DOMAIN>` с паролем. Без введённых секретов/домена Compose откажет.

## Схема и эксплуатация

- Caddy публикует только 80/443 и требует Basic Auth по HTTPS. Внешние `/api/*`
  дополнительно требуют X-API-Key. API/UI не публикуют собственные порты.
- UI передаёт API_KEY серверным запросом во внутренней сети. Он не добавляется в браузерный JS.
- API и UI находятся во внутренней Docker-сети без прямого выхода в интернет;
  анализатору нельзя динамически скачивать веса. Будущие локальные веса и зависимости
  подключать отдельным проверенным изменением после разрешения на новые данные.
- SQLite и временные загрузки находятся в томе jobs. Только один API-экземпляр;
  `--workers 1`, без реплик и без `--reload`.
- Контейнеры приложения работают непривилегированным пользователем, с read-only root,
  временной файловой системой и лимитами памяти/процессов. Подбор ресурсов для реальной
  модели ещё требуется. При больших MOV повысить /tmp осознанно: multipart также занимает место.
- В шаблоне MAX_UPLOAD_MB=100, MAX_PENDING_JOBS=2, JOB_TTL_SEC=3600. Лимит UI 100 MiB.
- `/healthz` подтверждает только здоровье API, а не наличие модели. Журналы доступа API
  отключены, в Caddy access log не включён. Не включайте дампы запросов/кадров/окружения.
- Том с SQLite хранит JPEG до TTL; доступ к хосту и резервным копиям должен быть ограничен.

После запуска на согласованном хосте проверить login, MOV с искусственной геометрией,
status=done/demo, перезапуск и очистку. Не использовать реальные видео до разрешения.
Перезапуск: `docker compose -f compose.json restart api`. Незавершённые задачи станут failed.
Остановка: `docker compose -f compose.json down`; том с результатами сохраняется.
Удаление тома — отдельное действие оператора по согласованной политике хранения.

Синтаксис конфигурации: [Docker Compose](https://docs.docker.com/reference/compose-file/services/),
[Caddy Basic Auth](https://caddyserver.com/docs/caddyfile/directives/basic_auth).
Теги образов заданы по версиям; перед публикацией рекомендуется зафиксировать проверенные
digest образов. Выпуск контейнера и полный TLS smoke-test остаются обязательными проверками среды.
