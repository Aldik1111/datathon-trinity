# Trinity — локальный сервис проверки видео

Универсальная основа: FastAPI, очередь задач, SQLite, Streamlit и контракт
подключения локального анализатора. Датасет, обученная модель, признаки,
предсказания и нормативные утверждения в эту версию не входят.

По умолчанию включён **демонстрационный режим**: он создаёт явно тестовое событие
и показывает кадр загруженного пользователем видео. Это проверка интерфейса,
не распознавание нарушений. Никакие входные файлы не обрабатываются автоматически.
Облачные AI API не используются. Идентификация лиц не реализована.

## Запуск

Python 3.12. Команды из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe scripts/init_env.py
.\.venv\Scripts\python.exe -m pytest tests -q
```

Генератор создаёт .env со случайным API-ключом, существующий файл не меняет.
В .env установите ANALYZER_MODE=demo для демонстрации. Ключ не публикуйте.
Запустите два терминала:

```powershell
.\.venv\Scripts\python.exe -m uvicorn src.api.app:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

```powershell
.\.venv\Scripts\python.exe -m streamlit run src/ui/app.py --server.address 127.0.0.1 --server.port 8501
```

UI: http://127.0.0.1:8501. API: http://127.0.0.1:8000/docs.
Остановка — Ctrl+C. На Linux используйте .venv/bin/python; OpenCV может потребовать libGL.

## API

- POST /api/v1/analyze: MOV в multipart-поле file; HTTP 202 с job_id.
- GET /api/v1/jobs/{job_id}: processing / done / failed.
- Для обоих маршрутов нужен заголовок X-API-Key.
- Итоговый ответ содержит verdict и violations с типом, временем, описанием
  и 1–3 JPEG-кадрами в base64. В demo все события явно тестовые.
- Ошибка видео возвращает failed; она не маскируется отрицательным вердиктом.

Очередь и SQLite рассчитаны на один экземпляр API. ANALYZER_TIMEOUT_SEC не больше 300.
Загруженный временный MOV удаляется после обработки; результат с кадрами хранится
в SQLite до JOB_TTL_SEC. Эти файлы локальны и исключены из Git.

## Подключение собственного анализатора

Только после отдельного разрешения на новые данные подключите модуль через
ANALYZER_CALLABLE=модуль:функция и установите ANALYZER_MODE=real.
Функция получает путь к видео и возвращает AnalysisResult из src/vision/contracts.py.
Event содержит event_type, timecode_sec, description, evidence_frames и rule_id.
EvidenceFrame содержит timestamp_sec и jpeg_bytes. Пример структур есть в тестовых
анализаторах; они не являются моделями распознавания.

Реального анализатора в поставке нет. При его отсутствии real-задача завершится
ошибкой; безусловный отрицательный ответ не подставляется. В configs/rules.json
пустой реестр. Только независимо проверенные источники можно добавлять как verified.

## Проверки

Тесты создают искусственные изображения и короткие синтетические видео во временных
папках. Они проверяют API, авторизацию, очередь, JPEG, тайм-ауты, UI и расчёт метрик.
Внешних данных и обученных весов для запуска тестов не требуется.

evaluate.py — универсальная утилита; ей явно передаются --annotations, --splits
и --predictions для отдельно разрешённых данных. Никаких таблиц по умолчанию нет.
Публичный сервер не настроен; фактическое распознавание и его качество не заявлены.

## Интеграция и развёртывание

Командная инструкция: [docs/SERVICE_RUNBOOK.md](docs/SERVICE_RUNBOOK.md).
Проверка настоящего HTTP-сервера в отдельном процессе:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_http_process.py -q
```

Тест сам создаёт синтетический MOV, запускает Uvicorn на свободном loopback-порту,
проверяет очередь, дочерний процесс анализа, JPEG, SQLite и перезапуск, затем
останавливает сервер и удаляет временные файлы. Пользовательские видео не нужны.

`compose.yaml` готовит локальные API/UI с изолированной сетью и постоянным SQLite.
`deploy/compose.public.yaml` и `deploy/Caddyfile` — отдельная конфигурация HTTPS
и входа для жюри. Публичный запуск выполняется только после согласования среды.
Обычный запуск Compose открывает порты только на 127.0.0.1.
